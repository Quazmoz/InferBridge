# InferBridge 0.9.6-beta.1

This is a **beta pre-release** and its artifacts are **unsigned**. Windows will report an
unknown publisher and SmartScreen may warn on first launch. Nothing in this release has been
Authenticode signed, and no signing claim is made anywhere in its metadata. Verify downloads
against the published SHA-256 checksums.

It contains no new features. It is a reliability and release-integrity pass over
[0.9.5](0.9.5.md): two runtime defects that only appear when something has already gone wrong,
and the repair of three release gates that had stopped being able to pass.

## A corrupt recovery file no longer breaks model status

`_normalize_recovery_record` exists so that a recovery file which was hand edited, truncated,
or written by an older build cannot break model-status polling. It validated four fields with
`value not in {...}`, and set membership hashes the candidate.

- **An unhashable value crashed the guard itself.** A recovery file holding a JSON object or
  array in `operation_type`, `terminal_state`, `failed_stage`, or `last_completed_stage` raised
  `TypeError: unhashable type` out of the function whose entire purpose is to contain exactly
  that. The symptom was a 500 from the status poll the browser UI depends on, for as long as the
  file stayed on disk, with no route to recover the affected model.
- **The type is now checked before membership**, so a malformed value falls back to its documented
  default the same way any other unexpected value already did.

## Tray commands survive a contended write

`atomic_json` writes the tray command and heartbeat files that separate desktop processes use to
coordinate — second-launch activation, installer coordination, and the owned quit command. Each
writer already staged into its own temporary file, which makes the write atomic.

- **The replace onto the shared destination was still contended.** On Windows `MoveFileEx` fails
  with `ERROR_ACCESS_DENIED` or a sharing violation when another writer, an antivirus scanner, or
  a file-sync client holds the target open. Concurrent writers lost commands to an unhandled
  `PermissionError`, reproducibly rather than occasionally.
- **Transient failures are now retried** on a short bounded backoff, matching what
  `app.storage_safety` already does for the same class of Windows failure. A genuinely
  non-transient error still propagates unchanged.

## Release gate

Three gates in the release pipeline could no longer pass, so no release build could complete
from `beta`.

- **The packaged smoke test looked for markup that had moved.** It asserted the root document
  contains the string `About & Updates`. Since the browser client began serving feature payloads
  as content-addressed `/ui/` assets, that string lives in `ovllm-release-extension.<hash>.js`
  and never appears in the document, so the check failed against a correctly built package. It
  now follows the script reference and asserts against the asset, which additionally proves the
  asset endpoint serves the payload — something the original string match could not check.
- **Lint and formatting had drifted.** Eleven files no longer matched `ruff format`, two of them
  missing a trailing newline, and two lint errors had accumulated. Both Ruff gates run inside the
  release build.
- **Twenty-eight tests failed on a standard Windows account.** None of the failures were in the
  behaviour under test. Seven refusal tests could not stage a symbolic link, which needs
  Developer Mode or elevation on Windows, and now skip the way the equivalent tests elsewhere in
  the suite already did. Others had gone stale against deliberate production changes — the
  collision-safe diagnostics archive name, channel-scoped update caches, the loopback request-host
  requirement on the local-UI guard, and a browser extension added to the composition without
  being added to the declared order. Two diagnostics tests asserted POSIX redaction through
  `Path`, which is the host flavour, so on Windows they exercised a backslash path the POSIX
  pattern is not meant to match and proved nothing; they now use `PurePosixPath`. One test
  asserted an error message only reachable before `Settings` installs the safety stack, so it
  passed alone and failed in a full run.

## Verified in this release

Validated on an Intel Core Ultra 9 185H with Arc iGPU and AI Boost NPU, OpenVINO 2026.2.1:

- Real load, generation, streaming, repeated requests, and unload on **CPU, GPU, and NPU**.
- Mock-mode API contract, browser UI under Chromium, desktop launcher lifecycle including
  duplicate-launch handling and the owned quit command, and port-conflict behaviour.

Still unverified, as in every unsigned release: Authenticode signing, and installer upgrade and
downgrade against a real prior installation.
