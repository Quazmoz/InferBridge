# InferBridge 0.9.0-beta.1

This is a **beta pre-release** and its artifacts are **unsigned**. Windows will report an
unknown publisher. Install it only if you accept that, and prefer a signed stable release
for ordinary use. Nothing in this release has been Authenticode signed, and no signing
claim is made anywhere in its metadata.

It is also the first published build whose artifacts actually contain context budget
visibility, model preparation recovery, and stage-aware preparation watchdogs. The
published 0.8.0 release notes described those features, but they landed after the `v0.8.0`
tag was cut and are not present in the 0.8.0 installer or portable package. Published tags
are immutable, so this pre-release carries the corrected record.

## Highlights

### Model preparation recovery

- Persists sanitized recovery state after interrupted, cancelled, or failed conversion and loading operations.
- Distinguishes reusable Hugging Face source cache data from incomplete or complete OpenVINO conversion output.
- Adds a WebGUI recovery screen with resume, failed-stage retry, fresh-download restart, incomplete-output cleanup, and sanitized failure details.
- Keeps recovery actions operation-scoped with stale recovery-ID rejection behind the existing API-key and browser-origin protections.
- Refuses to remove complete models, symbolic links, paths outside the configured model directory, or the model-directory root.
- Composes recovery summaries into split model status and keeps inferred recovery identities stable across polling.
- Preserves stream cancellation precedence when a cancellation and a recovery race.

See [Model preparation recovery](../MODEL_RECOVERY.md) for the recovery contract and API.

### Stage-aware preparation watchdogs

- Adds separate download, conversion, finalization, loading, and OpenVINO compilation limits.
- Uses inactivity detection for download, conversion, and finalization so a slow operation stays valid while progress heartbeats continue; loading and native compilation use total stage deadlines.
- Reports the stalled stage and the last successful progress timestamp, and preserves reusable cache data, incomplete conversion output, complete converted models, and any previously loaded engine.
- Keeps an external cancellation request intact when a watchdog timeout fires at the same time.

### Context budget visibility

- Adds an exact tokenizer-backed chat preflight for the selected loaded model.
- Reports prompt use, context limits, output capacity, retained messages, pending attachment estimates, and the older whole turns that will be omitted.
- Reuses the generation path's message normalization, chat template, tokenizer, whole-turn sliding window, and output safety allowance, so the preflight and the request agree.
- Adds WebGUI actions to preserve the current draft in a fresh chat or reduce the requested output to the effective limit.
- Restricts attachment preflight to vision-capable models and avoids redundant preflight requests.

See [Context budget visibility](../CONTEXT_BUDGET.md) for calculation details and the API contract.

### Packaged runtime correctness

- Bundles the OpenVINO tokenizer runtime and registers packaged OpenVINO DLL search paths, so conversion works from the installed and portable packages.
- Hardens packaged native DLL discovery and classifies OpenVINO tokenizer runtime failures distinctly.
- Stops retrying other devices when a failure is a tokenizer packaging fault rather than a device fault.
- Contains packaged converter failures instead of letting them escape as unhandled errors.
- Adds an executable native-package validation step and requires the tokenizer DLL in the release gate.

### Release pipeline

- Fingerprints and caches the pinned release environment so repeat builds reuse a validated virtual environment.
- Builds the portable archive directly from the packaged tree instead of a staging copy, and verifies archive source parity.
- Publishes per-step release timing telemetry and requires timing provenance.
- Deduplicates artifact scans and speeds up checksum generation.

### Desktop, tray, and onboarding

- Hands the resolved desktop data path to the server child process.
- Surfaces a packaged server startup exit immediately and stops readiness polling once the child exits.
- Moves expensive hardware-advisor telemetry off the request path while preserving its response contract.
- Opens onboarding automatically only on the first WebGUI visit, and removes a broken onboarding exit control.
- Makes onboarding state recovery atomic by quarantining an unreadable state file, and serializes read-modify-write updates under one lock.
- Registers source and editable installs with the `-m app.desktop_launcher` dispatch so Start with Windows launches InferBridge rather than an idle interpreter.

### Windows source and developer setup

- Validates the supported Python version during Windows setup and aligns the supported-version contract across setup, preflight, and tests.
- Adds an incremental developer package build and records source dependency profiles.
- Keeps Hugging Face tokens out of setup files and guards the secure Hugging Face setup flow.

### Interface

- Polishes the active operation queue, including progress-row accessibility.
- Improves compact header overflow menu keyboard behavior and focus reliability.
- Adds a safe Hugging Face search UI.
- Fixes stale workspace generation state.
- Reduces routine polling log noise while preserving errors and slow requests, and normalizes logged polling paths.

## Fixes

- The update checker treated a published version equal to the installed version as an upgrade, so the release that published the running build was offered as an available update on every check. Exact-version equality is now rejected.
- The preparation progress track reported every phase as determinate, so a phase with no measurable percentage rendered a bar pinned at 0% instead of the indeterminate animation. Determinacy is now derived from whether a percentage was actually reported.
- The monotonic overall-progress floor read an undefined property, producing `NaN`, and was never persisted across polls. It now combines the completed stage base with the current stage reading and carries forward correctly.
- An `auto_convert` load bounded the entire operation, including the nested download and quantization, by a single ten-minute deadline, so preparing a multi-gigabyte model failed mid-download. Only the native engine build is bounded now, and that backstop is derived from the configured preparation-watchdog budget instead of silently capping it.
- The authentication-failure map was pruned only for the requesting source, so it grew once per distinct client address for the process lifetime.

## Validation performed for this pre-release

Ruff lint and formatting, the full Python test suite, the external mock API contract, and
the packaged installed-mode and portable-mode mock smoke tests all passed in the pinned
release environment. Release provenance and SHA-256 checksums were verified independently
of the build.

## Not verified

Authenticode signing (these artifacts are unsigned), installer upgrade and downgrade on a
real Windows installation, real Intel CPU, GPU, or NPU execution, tokenizer behavior for
every converted model, and recovery behavior with every Hugging Face cache and checkpoint
layout. Those checks require the documented Windows release and hardware certification
procedures. A signed stable build must advance the version; see
[0.9.0](0.9.0.md) for the planned stable release record.
