# InferBridge 1.1.1-beta.1 — beta

Beta promoted from the 1.1.1-dev.1 nightly, following the 1.1.0 stable release and the 1.1.0-beta.1 beta. This is a pre-release: the Windows installer and portable ZIP are **unsigned** (Windows SmartScreen will warn on first launch) and are not hardware-qualified.

## Highlights since 1.1.0-beta.1

- **Connect a tool.** Setup cards on the native Local API page and the browser Connection Hub for Continue, GitHub Copilot CLI, VS Code GitHub Copilot Chat (Custom Endpoint, plus a labelled snippet for the deprecated `customOAIModels` setting), the GitHub Copilot app, Cline, Roo Code/Zoo Code and generic OpenAI-compatible apps, with values from the running engine, copy buttons, numbered steps, a context-window note for agentic tools and a Test connection button. The native app offers confirmed one-click setup with Undo for Continue (`config.yaml` merge with backup; malformed files are refused untouched) and Copilot CLI (user environment variables; copyable PowerShell in the Store edition). No real API key is written anywhere. Connection Hub metadata reports `context_tokens` and `max_output_tokens` for loaded generation models. See [Connect a tool](../CONNECTION_HUB.md#connect-a-tool).
- **Per-model context editor.** Native Model library cards show `Context: N tokens` with **Context…** and **Load with context…**; Chat shows the current model's context beside the Context used ring; Settings lists every model's context with **Edit…**. One shared editor (also in the browser Model Library) validates against the model's `config.json` limits, shows the architecture maximum, the recommendation and a KV-cache estimate, offers 2K–128K presets plus a custom value, and works without loading the model (**Apply now** reloads the engine and keeps the chat). New `GET /v1/models/contexts`; `POST /v1/models/load` accepts `context_tokens`. See [Context budget](../CONTEXT_BUDGET.md#adaptive-model-context-configuration).
- **KV cache precision and larger context.** Per-model **KV cache precision** in the native and browser editors: Auto (default), FP16, INT8 (`u8`) or INT4 (`u4`), sent as `KV_CACHE_PRECISION` to CPU and GPU loads only, never to NPU, `AUTO` or composite devices. Estimates follow the chosen precision, a **max for this model** preset appears when `config.json` states the limit, and a rejected precision keeps the previous engine and explains the fix. INT4 KV on GPU needs OpenVINO 2026.2 or later. `POST /v1/models/context` and `POST /v1/models/load` accept `kv_cache_precision`. Defaults are unchanged. New guide: [Context and memory](../CONTEXT_AND_MEMORY.md), with a **Benchmark results** issue form and `docs/benchmarks/`.
- **Native chat parity with the browser.** **Eject** (Ctrl+Shift+E; unloads the model, keeps the conversation and does not silently reload it on the next send; only the engine's 409 "busy" refusal is retried), a **Load another model?** guard, **Regenerate**, a **context budget** chip backed by `/v1/chat/context-budget` (omitted turns listed, **Reduce reply to fit**), starter prompts, Esc / Ctrl+L, saved generation defaults, a theme setting, **Recent engine activity**, **Best model for this PC** (explicit Download and load) and **Check for newly verified models…**. Per-message stats, queue-while-loading and jump-to-latest are deliberately not added; `trust_remote_code` stays browser-only. See [Native feature parity](../NATIVE_FEATURE_PARITY.md).
- **NPU compile failures you can act on (#65).** NPU-targeted conversions use channel-wise INT4 (group size -1, symmetric, ratio 1.0) for Phi-4-mini, models above about 4B parameters and 3B+ models on NPU 3720; an explicit group size still wins. When the driver rejects an NPU load (`ZE_RESULT_ERROR_INVALID_ARGUMENT` or "Failed to compile. No more devices are left"), the browser and native app explain the likely causes and offer **Update Intel NPU driver**, **Load on GPU instead** and **Reconvert for NPU (channel-wise INT4)**; InferBridge never switches devices by itself. Phi-4 Mini carries an NPU known-issue caveat and diagnostics include `NPU_DRIVER_VERSION`. Not yet exercised on Meteor Lake hardware.
- **Clipboard fallback.** Copy diagnostics falls back to `clip.exe`, then to saving a file and showing its path, when the Windows clipboard is unavailable.

## Release and packaging

- The release channel defaults to `auto`, derived from `app/version.py` (no suffix -> stable, beta/rc -> beta, dev or other suffix -> nightly); an explicit channel that does not fit the version is refused with the branch or channel to use instead. The resolved version, channel and branch are logged before the build.
- **Packaged smoke diagnostics.** The frozen tray reports a failed headless startup on stderr and in its log (exit 6 with the reason) instead of only exiting; packaged smoke captures tray stdio, prints redacted tray logs on failure (bearer tokens redacted before key/value secrets), picks an `OV_LLM_PORT` free on both wildcard and loopback, and can repeat runs on a 2-core affinity. A manual **Packaged Windows smoke** GitHub workflow runs the real release builder.
- New tag-driven **GitHub Release** workflow: pushing `v<version>` builds the unsigned release through `scripts/build_release.ps1` (tests and installed/portable packaged smoke), verifies provenance and checksums, and publishes the assets as a GitHub Release (pre-release for beta).
- GitHub issue templates point to **Send feedback** instead of "beta feedback".

## Compatibility and security

- Data schema remains 1; no persistence migration is included.
- The MSIX identity version derives from this version as 1.1.1.0.
- Artifacts are unsigned. Native chat parity features are covered by source and mocked-HTTP contract tests only; physical CPU/GPU/NPU operation, installed upgrade/downgrade and Microsoft Store certification are not verified.
