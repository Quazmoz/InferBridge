# InferBridge 1.1.1-dev.1 — nightly evaluation

Development-channel evaluation build following the 1.1.0 stable source baseline. This is not a stable release or a production certification.

## Highlights

- Azure pipeline and `scripts/build_release.ps1` default to release channel `auto`, derived from `app/version.py` (no suffix -> stable, beta/rc -> beta, dev or other suffix -> nightly). An explicit channel can still be chosen and is refused, with the branch or channel to use instead, when it does not fit the version.
- The resolved version, channel and source branch are logged before the build starts.
- **Connect a tool** on the native Local API page and the browser Connection Hub: setup cards for Continue, GitHub Copilot CLI, VS Code GitHub Copilot Chat (Custom Endpoint, plus a labelled snippet for the deprecated `customOAIModels` setting), the GitHub Copilot app, Cline, Roo Code/Zoo Code and generic OpenAI-compatible apps. Values come from the running engine; each card has copy buttons, numbered steps, a context-window note for agentic tools and a Test connection button that reuses the self-test. The native app offers confirmed one-click setup with Undo for Continue (`config.yaml` merge with backup; malformed files are refused untouched) and Copilot CLI (user environment variables; copyable PowerShell in the Store edition). No real API key is written anywhere. See [Connect a tool](../CONNECTION_HUB.md#connect-a-tool).
- Connection Hub metadata now reports `context_tokens` and `max_output_tokens` for loaded generation models.
- **Per-model context, where models live.** Every native Model library card shows `Context: N tokens` with **Context…**, and unloaded models offer **Load with context…**; Chat shows the current model's context with **Context…** / **Change…** beside the Context used ring; Settings lists every model's context with **Edit…**. One shared editor validates against the model's `config.json` limits, shows the architecture maximum, the recommendation and a KV-cache estimate, offers 2K–128K presets (capped at the model maximum) plus a custom value, marks values above the recommendation as trial, and works without loading the model: **Apply now (reloads engine, chat kept)** for loaded models, otherwise **Used next time this model loads**. The browser Model Library has the same editor. New `GET /v1/models/contexts`; `POST /v1/models/load` accepts `context_tokens`; Connect a tool limits follow the saved value. The old Settings-only picker was replaced. See [Context budget](../CONTEXT_BUDGET.md#adaptive-model-context-configuration).
- **KV cache precision and larger context.** The context editor (native and browser) adds a per-model **KV cache precision**: Auto (OpenVINO's own choice, the default), FP16, INT8 (`u8`) or INT4 (`u4`). Explicit values are sent as `KV_CACHE_PRECISION` to CPU and GPU loads only, never to NPU, `AUTO` or composite devices. KV-cache estimates follow the chosen precision (about 0.57x and 0.32x of FP16; estimates, not measured memory), a **max for this model** preset appears when `config.json` states the limit, and each editor explains why the defaults are NPU-safe and how far CPU/GPU can go. INT4 KV on GPU needs OpenVINO 2026.2 or later; a rejected precision keeps the previous engine and says how to fix it. `POST /v1/models/context` and `POST /v1/models/load` accept `kv_cache_precision`. Defaults are unchanged. See [Context and memory](../CONTEXT_AND_MEMORY.md).
- **NPU compile failures you can act on (#65).** Conversions targeted at the NPU now use channel-wise INT4 (group size -1, symmetric, ratio 1.0) for Phi-4-mini, for models above about 4B parameters and for 3B+ models on NPU 3720; an explicit group size still wins. When an NPU load is rejected by the driver (`ZE_RESULT_ERROR_INVALID_ARGUMENT` or "Failed to compile. No more devices are left"), the error explains the likely causes and both the browser and native app offer **Update Intel NPU driver**, **Load on GPU instead** and **Reconvert for NPU (channel-wise INT4)**; InferBridge never switches devices by itself. Phi-4 Mini carries an NPU known-issue caveat, diagnostics include the NPU driver version (`NPU_DRIVER_VERSION`), and Copy diagnostics falls back to `clip.exe`, then to saving a file and showing its path, when the Windows clipboard is unavailable. Not yet exercised on Meteor Lake hardware.
- **New guide: [Context and memory](../CONTEXT_AND_MEMORY.md)**, covering larger context in native, web and API, KV cache precision, adjusting the bundled models, why the defaults are small, NPU notes and how to contribute benchmark results (template, `docs/benchmarks/` and a new **Benchmark results** issue form).
- **Native chat parity with the browser.** The native Chat model bar gains **Eject** (Ctrl+Shift+E; unloads the model, keeps the conversation, and does not silently reload it on the next send; only the engine's 409 "busy" refusal is retried), a **Load another model?** guard when other models are loaded, **Regenerate**, a **context budget** chip that asks the engine's `/v1/chat/context-budget` with the exact next request (omitted turns listed, **Reduce reply to fit**), starter prompts on an empty chat, and Esc (stop) / Ctrl+L (new chat). Generation settings can be saved as defaults, and Settings → Appearance adds a theme (Windows setting, Light or Dark) (both stored locally). The Engine & devices page adds **Recent engine activity** (engine event log) and **Best model for this PC** (the engine hardware advisor, with explicit Download and load; it never switches chat by itself). Model library → Import / export adds **Check for newly verified models…**, the browser's Refresh of the official verified model list (no model files are downloaded and your own definitions are never replaced).
- Deliberately not added to native: per-message timestamps and stats, queue-while-loading and jump-to-latest. The onboarding wizard and the Hugging Face gated-access dialog remain partial in native, and `trust_remote_code` stays browser-only for security. [Native feature parity](../NATIVE_FEATURE_PARITY.md) was corrected: neither side has an embedding playground.
- All native chat parity features are covered by source and mocked-HTTP contract tests only; they have not yet been exercised on Windows hardware or in an installed package.
- GitHub issue templates point to **Send feedback** instead of "beta feedback".

## Compatibility and security

- Data schema remains 1; no persistence migration is included in this version update.
- Azure evaluation artifacts are unsigned and must not be represented as qualified or signed releases.
