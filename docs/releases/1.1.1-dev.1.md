# InferBridge 1.1.1-dev.1 — nightly evaluation

Development-channel evaluation build following the 1.1.0 stable source baseline. This is not a stable release or a production certification.

## Highlights

- Azure pipeline and `scripts/build_release.ps1` default to release channel `auto`, derived from `app/version.py` (no suffix -> stable, beta/rc -> beta, dev or other suffix -> nightly). An explicit channel can still be chosen and is refused, with the branch or channel to use instead, when it does not fit the version.
- The resolved version, channel and source branch are logged before the build starts.
- **Connect a tool** on the native Local API page and the browser Connection Hub: setup cards for Continue, GitHub Copilot CLI, VS Code GitHub Copilot Chat (Custom Endpoint, plus a labelled snippet for the deprecated `customOAIModels` setting), the GitHub Copilot app, Cline, Roo Code/Zoo Code and generic OpenAI-compatible apps. Values come from the running engine; each card has copy buttons, numbered steps, a context-window note for agentic tools and a Test connection button that reuses the self-test. The native app offers confirmed one-click setup with Undo for Continue (`config.yaml` merge with backup; malformed files are refused untouched) and Copilot CLI (user environment variables; copyable PowerShell in the Store edition). No real API key is written anywhere. See [Connect a tool](../CONNECTION_HUB.md#connect-a-tool).
- Connection Hub metadata now reports `context_tokens` and `max_output_tokens` for loaded generation models.
- **Per-model context, where models live.** Every native Model library card shows `Context: N tokens` with **Context…**, and unloaded models offer **Load with context…**; Chat shows the current model's context with **Context…** / **Change…** beside the Context used ring; Settings lists every model's context with **Edit…**. One shared editor validates against the model's `config.json` limits, shows the architecture maximum, the recommendation and a KV-cache estimate, offers 2K–128K presets (capped at the model maximum) plus a custom value, marks values above the recommendation as trial, and works without loading the model: **Apply now (reloads engine, chat kept)** for loaded models, otherwise **Used next time this model loads**. The browser Model Library has the same editor. New `GET /v1/models/contexts`; `POST /v1/models/load` accepts `context_tokens`; Connect a tool limits follow the saved value. The old Settings-only picker was replaced. See [Context budget](../CONTEXT_BUDGET.md#adaptive-model-context-configuration).
- **KV cache precision and larger context.** The context editor (native and browser) adds a per-model **KV cache precision**: Auto (OpenVINO's own choice, the default), FP16, INT8 (`u8`) or INT4 (`u4`). Explicit values are sent as `KV_CACHE_PRECISION` to CPU and GPU loads only, never to NPU, `AUTO` or composite devices. KV-cache estimates follow the chosen precision (about 0.57x and 0.32x of FP16; estimates, not measured memory), a **max for this model** preset appears when `config.json` states the limit, and each editor explains why the defaults are NPU-safe and how far CPU/GPU can go. INT4 KV on GPU needs OpenVINO 2026.2 or later; a rejected precision keeps the previous engine and says how to fix it. `POST /v1/models/context` and `POST /v1/models/load` accept `kv_cache_precision`. Defaults are unchanged. See [Context and memory](../CONTEXT_AND_MEMORY.md).
- **NPU compile failures you can act on (#65).** Conversions targeted at the NPU now use channel-wise INT4 (group size -1, symmetric, ratio 1.0) for Phi-4-mini, for models above about 4B parameters and for 3B+ models on NPU 3720; an explicit group size still wins. When an NPU load is rejected by the driver (`ZE_RESULT_ERROR_INVALID_ARGUMENT` or "Failed to compile. No more devices are left"), the error explains the likely causes and both the browser and native app offer **Update Intel NPU driver**, **Load on GPU instead** and **Reconvert for NPU (channel-wise INT4)**; InferBridge never switches devices by itself. Phi-4 Mini carries an NPU known-issue caveat, diagnostics include the NPU driver version (`NPU_DRIVER_VERSION`), and Copy diagnostics falls back to `clip.exe`, then to saving a file and showing its path, when the Windows clipboard is unavailable. Not yet exercised on Meteor Lake hardware.
- **New guide: [Context and memory](../CONTEXT_AND_MEMORY.md)**, covering larger context in native, web and API, KV cache precision, adjusting the bundled models, why the defaults are small, NPU notes and how to contribute benchmark results (template, `docs/benchmarks/` and a new **Benchmark results** issue form).
- **Native chat parity with the browser.** The native Chat model bar gains **Eject** (Ctrl+Shift+E; unloads the model, keeps the conversation, and does not silently reload it on the next send; only the engine's 409 "busy" refusal is retried), a **Load another model?** guard when other models are loaded, **Regenerate**, a **context budget** chip that asks the engine's `/v1/chat/context-budget` with the exact next request (omitted turns listed, **Reduce reply to fit**), starter prompts on an empty chat, and Esc (stop) / Ctrl+L (new chat). Generation settings can be saved as defaults, and Settings → Appearance adds a theme (Windows setting, Light or Dark) (both stored locally). The Engine & devices page adds **Recent engine activity** (engine event log) and **Best model for this PC** (the engine hardware advisor, with explicit Download and load; it never switches chat by itself). Model library → Import / export adds **Check for newly verified models…**, the browser's Refresh of the official verified model list (no model files are downloaded and your own definitions are never replaced).
- Deliberately not added to native: per-message timestamps and stats, queue-while-loading and jump-to-latest. `trust_remote_code` stays browser-only for security. [Native feature parity](../NATIVE_FEATURE_PARITY.md) was corrected: neither side has an embedding playground.
- **Native first-run wizard, Hugging Face access dialog and remembered settings.** The native app now has the browser's seven-step onboarding wizard over the same `/v1/onboarding` endpoints (it opens by itself once while the engine reports setup as not completed; **Setup and onboarding** in Best model for this PC reopens it), the browser's Hugging Face gated-access dialog (**Configure token**, **Open model page**, **Check access again**; the original download is resent only after access is confirmed) with a **Gated** pill on model cards, and it remembers the chat device, the Combine devices target, the advisor profile and conversation retention across restarts. Contract-tested only; not yet exercised on Windows hardware or against a real gated repository.
- All native chat parity features are covered by source and mocked-HTTP contract tests only; they have not yet been exercised on Windows hardware or in an installed package.
- **One chat, one embedding and one reranker model loaded together.** InferBridge now keeps one resident model per role. Loading a chat model replaces only the loaded chat model, so an embedding model (and a reranker) stay loaded for RAG apps such as Open WebUI. Before a model joins the others, the combined memory is estimated and the load is refused with a clear message when it cannot fit, or when it would be a second model on the Intel NPU; **Load anyway** (`allow_resource_risk`) is always an explicit choice. The browser shows a slots strip with per-slot Unload and role badges with **Load as embedding model**; the native Model library adds a **Resident models** row and the same buttons. The load guard is now **Replace the loaded model?**. New `GET /v1/models/slots`, `slot` on load and unload, and `role`/`slots` in `/v1/models`, `/health`, `/v1/models/status` and `/v1/system/status`. See [API contract](../API_CONTRACT.md#resident-model-slots-local-extension) and [Device support](../DEVICE_SUPPORT.md#several-resident-models-and-the-npu). Not yet exercised on NPU hardware.
- **Local reranking for RAG: `POST /v1/rerank`.** A Cohere/Jina-compatible rerank endpoint (aliases `/rerank` and `/v2/rerank`) runs cross-encoder rerankers with OpenVINO GenAI's `TextRerankPipeline` in the new reranker slot, beside the chat and embedding models. Two rerankers are available: **BGE Reranker Base** (in `models.json` and the Verified Model Library) and **BGE Reranker v2 M3** (multilingual, Verified Model Library). Scores are 0–1 (sigmoid of the cross-encoder logit), up to 512 documents per request, scored in batches of 32. The import forms (browser and native) and the custom-model form gain a **Reranker** backend, Hugging Face search suggests it for reranker repositories, and the browser Connection Hub adds **Rerank for RAG** with a curl example and a scoring form. Setup for Open WebUI, Dify and LlamaIndex is in the new [Reranking](../RERANK.md) guide. Rerankers are not hardware-certified yet. The native Local API page has the same **Rerank for RAG** test panel (disabled with guidance until a reranker is loaded).
- **Combined CPU/GPU/NPU device modes, checked before they compile (experimental).** A new resolver classifies `AUTO`, `AUTO:<list>`, `HETERO:<list>` and cumulative AUTO per backend (chat, vision, embedding, rerank) as supported, experimental or unsupported, with the reason, and `GET /v1/devices/modes` reports it. Unsupported combinations (for example an NPU inside HETERO or cumulative AUTO for a chat model) and unavailable members return a friendly `400` before any compile; **Load anyway** (`allow_resource_risk`) stays an explicit choice. OpenVINO deprecated `MULTI`, so saved `MULTI:<list>` choices load as `AUTO:<list>` with cumulative throughput, with a one-time notice. AUTO chat loads send `PERFORMANCE_HINT=LATENCY` by default (`performance_hint` overrides it), and `HETERO:GPU,CPU` can split a model too large for GPU memory with `model_distribution: "pipeline_parallel"` (an OpenVINO preview). A combined load that fails offers **Load on GPU instead** or **Load on CPU instead** and records the offer in diagnostics; InferBridge never switches devices by itself. The NPU coexistence rule now resolves members (plain `AUTO` never uses the NPU). Device pickers (web and native) now suggest `AUTO:<list>` and `HETERO:GPU,CPU` instead of `MULTI` and NPU-inside-HETERO, and the web picker disables combinations the engine classifies as unsupported for the selected model, showing why. Benchmark Lab (web) adds **Compare combined modes**. Model and slot rows add `execution_devices` and `resolved_device`; OpenVINO GenAI does not report where AUTO landed yet, so it stays empty outside mock mode. Verified facts and sources are in [Device support](../DEVICE_SUPPORT.md#combined-device-modes-experimental). Not yet exercised on Core Ultra hardware.
- **Combine devices builder (experimental), browser and native.** Pick two or three detected devices, order them with Move up / Move down, and choose AUTO priority, AUTO cumulative throughput (the browser's first control for cumulative AUTO), HETERO or HETERO pipeline-parallel. Every mode shows the engine's explanation and an Experimental badge; modes the engine marks unsupported for the selected model are disabled with the reason. The chosen target joins the device picker, and loads and device switches send `performance_hint` / `model_distribution`. New `GET /v1/devices/modes?members=…` builder evaluation. Native Benchmark Lab adds **Compare combined modes**. Mock-tested only.
- **AUTO exclusions and a GPU memory suggestion.** `AUTO:-CPU`-style exclusions (documented by OpenVINO 2026) are accepted and classified; like plain AUTO they never pick the NPU, and mixing exclusions with a priority list is refused. When a chat model's estimate exceeds the reported GPU memory but fits GPU plus free RAM, the hardware advisor adds `device_suggestion` (HETERO:GPU,CPU pipeline-parallel, experimental) and both device pickers show it as a suggestion only.
- GitHub issue templates point to **Send feedback** instead of "beta feedback".
- **Fixed: the Microsoft Store package crashed at launch.** The package-root `resources.pri` held only the logos and replaced the native client's own resource index, so the installed app failed with `0xC000027B` (the 2026-10-30 certification failure). The root index now includes the client's resources, and `dev` CI installs a structural MSIX and requires its window to stay open. The complete `dev` package then passed the installed smoke test and WACK (overall PASS, two optional findings) on `windows-2022` ([run 43574626614](https://github.com/Quazmoz/InferBridge/actions/runs/43574626614)); it has not been repeated on Windows 11 or on a stable candidate. See [Microsoft Store](../MICROSOFT_STORE.md#certification-rejection-2026-10-30).

## Linux edition

- **Packages and a single command.** Linux builds now ship as a `.deb` (Ubuntu 22.04/24.04, Debian 12), an `.rpm` (Fedora) and the portable tarball, all from one hash-locked private runtime. The packages install the read-only application in `/opt/inferbridge`, `/usr/bin/inferbridge`, a menu entry with Open/Quit actions, a themed icon and a systemd *user* unit; nothing runs as root and no service is enabled for you. The new `inferbridge` command covers `start`, `stop`, `status`, `open [--app-window]`, `logs`, `doctor`, `service enable|disable|…`, `autostart`, `install` (register a tarball for your user, also the tarball upgrade path), `uninstall [--purge --yes] [--remove-app]` and `update-check`. Upgrades replace only unmodified InferBridge-managed files; a unit or entry you edited is kept and reported. See [InferBridge on Linux](../LINUX.md).
- **`inferbridge doctor`** checks the GPU/NPU kernel driver binding (i915/xe, intel_vpu), `/dev/dri` and `/dev/accel` permissions, render-group membership (including "added but not logged in again"), the OpenCL/Level Zero/NPU user-space drivers, the kernel version, the keyring and data-directory permissions, compares them with what OpenVINO lists, and prints exact fix commands for Ubuntu/Debian and Fedora. `--check-devices` includes the same findings.
- **Keys survive restarts.** API keys created in the UI and the Hugging Face token are stored in the desktop keyring (Secret Service via `secret-tool`) when available, otherwise for the session only; never on disk.
- **Fixed: about 1 in 64 server launches and restarts failed** on every platform (Windows too) when the random instance nonce began with `-` and was parsed as an option. This was the cause of the intermittent "Packaged application check exceeded its deadline" CI failures.
- The data directory is created private (0700); configuration, onboarding state and logs are always private. Desktop helpers (browser, `xdg-open`, dialogs, clipboard, `systemctl`, `secret-tool`) no longer inherit the bundle's private Python environment or API/HF credentials.
- The in-app update check no longer offers the Windows installer to Linux users; it points to the release page and its Linux checksums.
- **Release pipeline:** a version tag now also builds, qualifies and attaches `InferBridge-<version>-linux-x86_64-portable.tar.gz`, `.deb`, `.rpm`, `InferBridge-<version>-linux-sbom.spdx.json` (SPDX 2.3) and `InferBridge-<version>-linux-SHA256SUMS.txt`, with a GitHub build-provenance attestation. `dry_run` builds and verifies them from a branch without publishing.
- **CI:** fresh-user .deb install with an upgrade and the systemd `--user` lifecycle on Ubuntu 22.04 and 24.04; minimal-image .deb/.rpm installs on ubuntu:22.04, ubuntu:24.04, debian:12 and fedora:44; a tarball upgrade from the previous `dev` build; uninstall and purge must leave no stray files; real CPU chat and streaming through the packaged app's OpenAI API with a tiny random-weight model.
- Not verified: Intel GPU/NPU execution on Linux hardware, graphical GNOME/KDE sessions on Wayland/X11 and the tray icon.

## Compatibility and security

- **Privacy: OpenVINO usage telemetry is now declined by default.** `openvino-telemetry` (used by NNCF and OVC during model conversion) treats a missing consent file as consent, so conversions could write a client ID to `%LOCALAPPDATA%\Intel Corporation` (`~/intel` on Linux) and send usage events. Every InferBridge process, including the conversion helper, now reads a missing consent file as declined; an explicit `opt_in_out --opt_in` is respected and `OV_LLM_ALLOW_OPENVINO_TELEMETRY=1` restores the library default. See [Data paths](../DATA_PATHS.md#files-outside-the-data-root-openvino-usage-telemetry).
- The **Rerank for RAG** curl examples (browser and native) pipe the JSON body on stdin, so the copied command also works in Windows PowerShell 5.1, which strips the quotes from a JSON argument.

- Data schema remains 1; no persistence migration is included in this version update.
- Azure evaluation artifacts are unsigned and must not be represented as qualified or signed releases.
